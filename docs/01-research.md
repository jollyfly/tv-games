# 01 · 调研报告

**项目工作名：** 数字岛大冒险（Number Island）
**目标：** 在小米电视上运行、只用电视遥控器操作、面向 4–5 岁儿童的数字与逻辑启蒙闯关游戏
**调研日期：** 2026-11-13
**本文性质：** 设计评审材料，不代表已开始编码

---

## 0. 结论先行

1. **技术路线可行。** 采用「原生 Android 壳 + WebView + 内嵌 HTML/CSS/JS/SVG」适合这个项目：画面可以全部由原创 SVG 构成，迭代快，APK 小，且能离线运行。风险主要不在“能不能跑”，而在**不同年份小米电视的 WebView 版本**和**遥控器按键差异**，需要真机验证。
2. **交互必须为遥控器重新设计，不能把触屏儿童游戏缩小搬上电视。** 全游戏只使用「左 / 右 / OK / 返回」，提示语以语音和图形为主，不要求孩子识字。
3. **4–5 岁的内容重点不是刷算式。** 核心是数数（一一对应、基数）、数字与数量对应、比较多少、顺序与相邻数、序数、规律；抽象加减只作为后续扩展。用具体物品、五格/十格结构、分层提示来支撑理解。
4. **首版建议做 10 关、每关 3 题、3 个世界。** 单个孩子连续玩 8–12 分钟可完成一个世界；配合护眼休息提示。量级足够形成完整游戏，又不会让首版失控。
5. **先按“家庭侧载 APK”交付原型，不按应用商店上架做。** 小米应用商店上架需要企业开发者、软著、ICP 等资质，且审核周期长；若后续要上架，再单独做合规和分发适配。

## 1. 平台与分发约束

### 1.1 小米电视的运行形态

小米电视使用 Android 底层 TV 系统（现行产品线为小米澎湃 OS / HyperOS TV）。对开发者的直接含义：

- 游戏以 **Android APK** 交付即可安装运行。
- 小米开发文档要求电视应用在 manifest 中声明电视特性：

  ```xml
  <uses-feature
      android:name="android.hardware.type.television"
      android:required="true" />
  ```

- 小米电视以遥控器为默认、也必须支持的输入设备。官方要求**所有内容与功能都能用遥控器完成**，不能依赖鼠标或触摸。
- 电视没有 Google Play 服务依赖。应用应完全离线、自包含，不依赖网络和第三方账号体系。

### 1.2 遥控器按键事实

小米官方开发文档列出的主要键值：

| 按键 | Android KeyCode | 对游戏设计的含义 |
|---|---|---|
| 上 / 下 / 左 / 右 | 19 / 20 / 22 / 21 | 主交互键。首版只用左右 + 上（重听） |
| OK / Center | 23（DPAD_CENTER） | 确认；必须支持 |
| Enter | 66（ENTER） | **官方要求同时支持**，部分遥控器/系统会发这个值 |
| 返回 | 4（BACK） | 取消/回退。首页按返回必须提示确认，不能直接退出 |
| 菜单 | 82（MENU） | 首版不使用 |
| Home | 系统处理 | 应用无法拦截；切后台时必须暂停 |
| Power / 音量 | 系统处理 | 不要与系统抢音量键；应用内做相对音量设置即可 |

> 小米遥控器的主页键、音量键一般由系统消费，应用无法监听；不要把关键功能设计在这两个键上。

### 1.3 安装与调试路径

据小米官方文档，电视应用有两种常用安装方式：

1. **U 盘 / 移动硬盘安装：** 将 APK 放入 U 盘，接到电视，用系统高清播放器访问并安装。需要在系统设置里允许安装未知来源应用。
2. **ADB 安装：** 在「设置 → 关于 → 产品型号」处连续按键打开开发者模式，开启网络 ADB，然后在同一局域网内 `adb connect <电视IP>:5555`，再安装 APK。

**当前开发环境没有连接小米电视，也没有安装 Android SDK / adb。** 在动工前需要确认目标电视型号和可用调试方式；真机有差异时，以真机为准。

### 1.4 显示与性能

- 主流电视输出 16:9 画面，设计以 **1920×1080** 为基准，向上兼容 4K，向下兼容 720p。
- 电视存在 **overscan（过扫描）**：边缘内容可能被裁掉。所有关键内容必须放在画面内缩约 **5%** 的安全区内。
- 观看距离通常 2–3 米，属于 **10-foot UI**：字号、焦点、对比度都必须大幅高于手机。
- 小米审核规范中明示：APK 上限约 **40 MB**，应用数据/内存上限约 **100 MB**。低端电视 GPU 性能有限，因此要避免重滤镜、超大位图和持续全屏动画。
- 全部使用 SVG 矢量资源有利于清晰度与包体，但 SVG 的 `filter`、模糊和高节点数会增加 GPU 负担；画面要“精美”，也要为低端设备设预算。

### 1.5 侧载与商店上架是两种完全不同的目标

| 维度 | 家庭侧载（首版建议） | 小米应用商店上架 |
|---|---|---|
| 面向用户 | 自己/亲友家的电视 | 中国大陆公开分发 |
| 资质 | 不需要 | 企业开发者、软件著作权、ICP 备案/许可证等 |
| 审核 | 无 | 商务、监管、运营、测试等多环节，官方说明约 7–10 个工作日 |
| 限制 | 需允许未知来源安装 | 儿童类不得有外链/购买入口，40MB 包体等 |
| 结论 | **先做这个，快速验证画面与遥控体验** | 后续再评估，别让合规拖住原型 |

小米审核规范明确把“简单打包的网站页面”列为不通过项。虽然我们的 HTML 会是完整的原创离线游戏，而不是网站套壳，但如果未来要上架，仍需准备原创内容、原生集成和完整可玩性来降低审核风险。**侧载原型阶段不受此限。**

### 1.6 WebView 可行性

- Android WebView 适合做 2D 卡通游戏：SVG、CSS 动画、Web Audio、Canvas 都能用；开发和改画面比原生 View 快。
- 需要按“电视上的系统 WebView”，而不是电脑 Chrome 来设计：
  - 不依赖最新浏览器 API；
  - 不依赖网络字体和远程资源；
  - 每个页面在 720p/1080p 下都能完整显示；
  - 避免 `backdrop-filter`、大面积模糊、复杂 SVG 滤镜；
  - 加载本地资源使用 Android 官方推荐的 **WebViewAssetLoader**，而不是 `file://`，避免文件域安全限制。
- 官方没有承诺所有年份的小米电视 WebView 都保持最新。**首版必须以目标电视实测为准**；若目标机型 WebView 过旧，再评估降级方案或退回原生 View。当前设计假设目标电视为近 5 年机型（Android 9+，WebView Chromium 80+）；低于此基线需真机确认。

## 2. 4–5 岁儿童与数感

### 2.1 这个年龄段的合理目标

教育部《3–6 岁儿童学习与发展指南》中，4–5 岁在“感知和理解数、量及数量关系”方面的典型目标包括：

- 通过数数比较两组物体的多少；
- 通过实际操作理解数与数之间的关系，例如 5 比 4 多 1，2 和 3 合在一起是 5；
- 会用数词描述事物的顺序和位置（序数）。

3–4 岁的对应目标是：一一对应比较、手口一致点数 5 个以内、按数取物；5–6 岁才逐步进入借助实物理解 10 以内加减。由此得到本项目的边界：

**4–5 岁核心内容**
- 1–10 的数字认读与数量对应；
- 手口一致点数、说出总数、按数取物；
- 比较两组数量多少；
- 数的顺序、相邻数、从 1 开始的正数；
- 序数（第几个）；
- 简单规律（AB、AABB）；
- 数的组成启蒙（5 可以分成 2 和 3）——可作为第二季或隐藏挑战，不作为首版主线的硬门槛。

**首版不做什么**
- 不刷口算题、不做计时应答、不排名；
- 不用抽象符号式算式作为主要练习；
- 不把“答对率”呈现给孩子，避免测试感；
- 不要求识字、写字或键盘输入。

### 2.2 数感教学法要点

- **一一对应：** 点一个、数一个；视觉上让每个物体可单独被高亮。
- **基数原则：** 数到的最后一个数，就是总数；反馈时重复“1、2、3，一共有 3 个”。
- **数量守恒：** 同样数量的物体换一种摆法，总数不变；可以用不同排列与“重新数一遍”建立。
- **数字—数量双向连接：** 既要从物体数量找数字，也要从数字找相应数量。
- **比较与关系：** 用并排、配对、十格框等方式让“多/少”可见，不只是口头判断。
- **最近发展区：** 孩子答错时给具体线索（“我们把它们一个一个数”），不要只给“再试一次”。
- **正向反馈：** 4–5 岁儿童对挫败更敏感；错误反馈应是温和的、可恢复的，最终一定能在支持下完成。

NAEYC 的家庭数学建议强调：手指、手势、画图、日常对话都是儿童理解数量的重要工具；同一个数量可以有不同表示方式。电视游戏无法做手指操作，但可以用高亮、点数动画、分组框和语音计数承担类似支架。

### 2.3 参考产品给出的启示

| 参考对象 | 可借鉴 | 不照搬 |
|---|---|---|
| Khan Academy Kids | 一个数字一个情境；数真实物品；声音与角色驱动 | 触屏拖拽、长流程课程 |
| Numberblocks（BBC） | 用可视化结构表现数量关系 | 视频形态与现有角色 IP |
| 都都数学 / Todo Math 等启蒙 App | 短关卡、即时反馈、难度渐进 | 密集 UI、付费体系、手机触控布局 |
| 儿童电视互动内容 | 大焦点、单任务、重复演示 | 依赖识字、遥控器按键过多 |

**共同空白：** 大量儿童数学产品是手机/平板触屏优先，搬到电视上容易出现焦点太小、需要拖拽、文字过多、遥控器不可达等问题。我们的差异点应该是：**为遥控器重新设计的、中文语音主导的、离线无广告的 10-foot 数字游戏。**

### 2.4 观看时长与家长共玩

- 首版一个世界约 5–8 分钟，完成三个世界约 20–25 分钟；建议每次玩 10–15 分钟。
- 设计“休息一下”提示作为家长可关闭的选项，默认在连续游戏约 15 分钟后出现。
- 家长区提供共玩提示（例如“让孩子用手指着屏幕数”“答错时先不告诉他答案”），把电视游戏变成亲子对话的起点，而不是电子保姆。
- 不收集儿童个人信息、不联网、无广告、无内购、无外链，这是产品底线，也是儿童类应用的基本信任基础。

## 3. 需求 → 设计结论

| 需求 | 调研结论 | 设计翻译 |
|---|---|---|
| 小米电视上运行 | Android APK + 遥控器 | 原生 Kotlin 壳 + WebView + 完全离线 |
| 电视遥控器控制 | 只能依赖方向/OK/返回 | 全局单焦点，左右选择，OK 确认，上键重听，返回回退 |
| 4–5 岁宝宝 | 不识字、注意力短、怕挫败 | 语音+图标指令，3 题一关，无计时，分层提示，完成即得星 |
| 数字与逻辑训练 | 数感 + 比较 + 顺序 + 规律 | 10 关课程矩阵，具体物品与结构化排列 |
| 画面精美、卡通 | 10-foot 观看 + 低端 GPU | 原创纸艺绘本风 SVG，大色块、清晰轮廓、克制滤镜 |
| 所有画面用 SVG | 矢量清晰、包体小 | 角色/场景/UI/数字全部原创 SVG；字体和音频单独授权/制作 |

## 4. 主要风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 电视 WebView 版本未知 | 动画/JS 不工作 | 真机先测版本；保守语法与 CSS；无网络资源；必要时降级 |
| 遥控器 OK 键值不一致 | 确认键无反应或双触发 | 同时支持 23/66；原生层统一映射并去重 |
| 返回键误触退出 | 孩子丢失进度或退出 | 首页返回必须二次确认；游戏中返回保留进度；家长区长按进入 |
| SVG 滤镜/节点过多 | 低端电视卡顿 | 画面预算、静态背景分层、只用 transform/opacity 动画 |
| 真人语音资源成本 | 非读者无法独立玩 | 首版先确定“机器配音/真人配音”方案；必须有语音 |
| 目标电视安装限制 | 无法侧载 | 提前确认型号；准备 U 盘与 ADB 两种路径 |
| 上架审核与资质 | 无法公开发布 | 首版定位家庭侧载；上架作为单独阶段评估 |
| 角色/字体/音频版权 | 侵权风险 | 角色和画面原创；字体仅用 OFL 字体；音频自制或明确授权 |

## 5. 需要在评审时确认的问题

1. **目标电视的具体型号/年份和遥控器型号？** 这决定 Android/WebView 基线、安装方式，以及是否能远程 ADB 调试。
2. **首版只要家庭侧载 APK，还是希望最终上架小米应用商店？** 后者需要企业资质、软著、ICP、审核等，是独立工作量。
3. **语音旁白：** 原型阶段可以接受机器中文配音吗？还是必须真人录音？这是 4–5 岁非识字用户的核心体验，必须尽早定。
4. **品牌：** 工作名“数字岛大冒险”、主角小狐狸“点点”和萤火虫“萤萤”是否 OK？是否需要换成孩子的小名/家庭元素？
5. **首版范围：** 10 关、约 30 题是否合适？是否需要加入“数字合体（5 的组成）”作为第 11 关或第二季？
